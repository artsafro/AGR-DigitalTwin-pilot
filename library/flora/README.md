# Flora agent library (#216)

One consolidated Flora library for agents: `catalogue.json` here, binaries outside Git
(`C:/x/flora-library/v002/` for the .max file; maps under `C:/x/flora-library/v001/maps/<slug>/`;
no PNG/TGA/TIFF in the repo).

## Files

- `species-curation.json` - the reviewed input: which #189 audit entries are one species, Latin + Russian name,
  type (tree / bush / hedge / flower / climber), and the entries that are still unresolved. Species that share one
  FLORIO mesh live in `shared_stand_in_gaps`, not in `species`. Edit this file, never `catalogue.json`.
- `maps.json` - per species diffuse + opacity paths and review status (`approved` only with the user's words).
  A gap species may keep a maps record; it is not a library species until it has its own mesh.
- `catalogue.json` - generated by
  `uv run python -m dt_ai.materials.flora_catalogue build --audit experiments/flora-library-audit/catalogue.json --curation library/flora/species-curation.json --maps library/flora/maps.json --previous library/flora/catalogue.json --identity library/flora/geometry-identity.json --out library/flora/catalogue.json`
  (`--identity` is optional; without it an explicit HP label is an unverified VPM and an `LP -> HP` label is not a VPM)
  and checked by `uv run python -m dt_ai.materials.flora_catalogue check --catalogue library/flora/catalogue.json`.
- `geometry-identity.json` - Max evidence of mesh identity (`flora-geometry-identity-v2`). World vertices come from
  `snapshotAsMesh` on the source copies (`tools/flora/dump_flora_source_vertices.py`, output outside the repo).
  Pair relations inside each curated species: translation-normalized symmetric Hausdorff `<= 1e-4` m is `same`,
  scale-normalized Hausdorff `<= 1e-4` relative is `scaled_copy`, otherwise `distinct`. Vertex counts must match
  for `same` and `scaled_copy`. Triangle counts never decide. Built by
  `uv run python -m dt_ai.materials.flora_catalogue identity --points <dump.json> --curation library/flora/species-curation.json --out library/flora/geometry-identity.json`.
- `tools/flora/build_flora_library_max.py` - headless 3ds Max assembly of `flora-library-v002.max` from scene copies.
  The pivot written there is the one described below.

## Gaps

`gaps.project_species_shared_stand_in` lists project species that still share one multi-species FLORIO stand-in.
They are not placed from this library. Each record is `{latin, russian, type, material_id, sources, status}`.
The material ID stays reserved for that species: it is not retired and it is not given to another species.
If the species later leaves the list, that ID is retired under its name and comes back with the species.
`gaps.unresolved` keeps unidentified meshes, with `status` and the audit `source_names`. No Latin name is invented.

## Material IDs

`retired_ids` is a list of `{material_id, latin, type}`, sorted by `material_id`. `latin` and `type` name the
species that held the ID. Both are null when a legacy catalogue retired a bare number; that number stays blocked
forever and is never recovered. An ID is never re-issued to another species; a returning species recovers its ID.
A new species takes the next free number of its range.

## VPM

`vpm_status` is `available` when a VPM mesh is chosen, `unconfirmed` when `vpm` is null and the NPM basis is
`LP -> HP` or a VPM candidate was skipped because its geometry identity with the NPM is unverified, or `none`
when there is no VPM. Identity evidence is `geometry-identity.json` (`flora-geometry-identity-v2`, tolerance
`1e-4`): `same` (translation-normalized symmetric Hausdorff `<= 1e-4` m), `scaled_copy` (after dividing each
cloud by its own largest bbox extent, Hausdorff `<= 1e-4` relative), or `distinct`. Vertex counts must match
for `same` and `scaled_copy`. Triangle counts never decide. A candidate is a VPM when the pair relation is
`distinct` (`vpm_identity` `verified_distinct`), or when the relation is unknown and the candidate is labelled
explicit HP (`vpm_identity` `unverified`). An `LP -> HP` candidate needs a verified distinct pair. `same` and
`scaled_copy` are duplicates of the NPM, not a VPM. `vpm_evidence` copies that pair (`relation` `distinct` or
`unknown`; deviations are null when the relation is unknown) and is null exactly when `vpm` is null.
`vpm_identity` is null exactly when `vpm` is null. `available` is the catalogue's match for a non-null `vpm`.
Known limit: two meshes that differ only in welded/unwelded vertices have different vertex counts and count as
`distinct`.

## How an agent picks a species for placement

1. Read the planting schedule row: Latin name (with cultivar if given), height, crown diameter, quantity.
2. Find the species in `catalogue.json` by `latin` (exact, cultivar included). No exact hit: try the species without
   the cultivar and report the substitution; still nothing: the species is new -> `model-flora` skill, texture route
   (#190), user review. Never substitute silently. A shared stand-in gap is not a library object: report it and do
   not place another species's mesh under that name.
3. Check height and crown against the schedule (+-20 %, [D099]); outside -> report, do not stretch past the band.
4. Merge the object `objects.NPM` (or `objects.VPM` when `vpm_status` is `available`) from the library .max.
   Its pivot is the centre of the world bbox in XY and 10 cm above the lowest vertex. Placing that pivot on the
   SPOZU point sinks the plant 10 cm into Ground [D100]. Do not add another 10 cm at placement. Random Z rotation
   and scale +-10 % still apply.
5. Keep the species' `material_id` on all faces (trees 101-199, bushes 201-299, hedges 301-399, flowers/beds
   401-499, climbers 501-599; 1-100 are never Flora). The atlas (#217) is built later from the placed scene.
6. `maps.review_status` other than `approved` -> the species can be placed for layout, but not delivered.
