**Границы измерения.** Первая команда — первая *команда сборки, названная в ответе*, не первая команда навигации или подготовки источника. Она не выполнялась. CLI выдаёт usage только при `turn.completed`: в таблице `input_tokens + output_tokens` за ход до ответа включительно; точный префикс до появления команды **не измерен**. Кэшированные входные и reasoning-токены не суммировались повторно. Файлы — уникальные явно адресованные пути, из которых в журнале виден текст (включая совпадения `rg` по указанным файлам); области широкого поиска и автоматическая загрузка контекста не посчитаны. По этой метрике чтений не стало меньше. Ни один AFTER-агент не вызвал `skeleton_guard.py --show`: отчёт про правильность выбора, а не подтверждение соблюдения новой последовательности.

**Воспроизведение.** Codex CLI 0.160.1, модель по умолчанию (идентификатор не раскрыт в JSONL). Четыре независимых `exec` в отдельных экспортах точных Git-деревьев без истории и папки с ключом. Один и тот же текст задачи до/после, режим read-only, без памяти и пользовательской конфигурации, `--ephemeral`. Отдельный предварительный прогон проверил чтение в Windows sandbox и исключён из результата. В четырёх зачётных журналах — только `Get-Content` и `rg`, без DCC, сборки, проверок модели или MCP; контрольные суммы файлов checkout не изменились. [Квитанция](entry-cost-1938.json) содержит ответы, usage, прочитанные пути, оценки и SHA-256 JSONL. Вложение к карточке `t_cc1ef690` содержит исходные замеры, журналы и скрипты воспроизведения.
