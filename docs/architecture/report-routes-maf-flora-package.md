# Карты маршрутов МАФ, Флоры и «Пакет и сдача» (#1393)

Продолжение #1383 / #1392 тем же методом: событийный штурм из YAML, схемы генерирует
`tools/architecture/route_map.py`, подписи на русском. Раньше МАФ, Флора и упаковка были одним блоком внутри карт
ВПМ ОКС и Ground; теперь у каждого свой маршрут и своя карта контекстов (Артём 2026-11-14).

| Схема | YAML (правится руками) | Схемы (только генератор) |
|---|---|---|
| Маршрут МАФ | `docs/architecture/maf-route.events.yaml` | `maf-route.excalidraw`, `maf-route.svg` |
| Маршрут Флоры | `docs/architecture/flora-route.events.yaml` | `flora-route.excalidraw`, `flora-route.svg` |
| Маршрут «Пакет и сдача» | `docs/architecture/package-route.events.yaml` | `package-route.excalidraw`, `package-route.svg` |
| Контексты МАФ | `docs/architecture/maf-contexts.yaml` | `maf-contexts.excalidraw`, `maf-contexts.svg` |
| Контексты Флоры | `docs/architecture/flora-contexts.yaml` | `flora-contexts.excalidraw`, `flora-contexts.svg` |
| Контексты «Пакет и сдача» | `docs/architecture/package-contexts.yaml` | `package-contexts.excalidraw`, `package-contexts.svg` |

Проверка: `uv run python tools/architecture/route_map.py --check` — выход 0, когда схемы совпадают с генератором,
каждая команда `agr` / `dt`, строка D, путь, функция владельца и строка дубля существуют, а карта контекстов
маршрута содержит каждый контекст его стадий с тем же владельцем. PNG для просмотра лежат на Drive
(`G:/Мой диск/AGR-evidence/1393-route-maps/` + `SHA256SUMS.txt`), в git их нет.

Правила, общие для трёх карт:

1. Каждый блок ссылается на источник: строку D из `docs/decisions.md`, путь инструмента или job. Чего в репо нет —
   красный блок с вопросом, а не догадка.
2. Шаги не привязаны к инструменту: «Агент: Blender / Max / AGR Tools» [D293 (1)].
3. Перед экспортом — стадия `npm` с двумя ветками: конвертация ВПМ → НПМ или параллельная расстановка low-poly и
   high-poly в одни точки [D293 (5)].
4. МАФ и Флора заканчиваются стадией `package`, которую раскрывает карта «Пакет и сдача».

## МАФ

12 стадий: спецификация и точки СПОЗУ (ветка: только визуализация — вне маршрута, D189) → кандидаты из библиотеки
(`G:/Мой диск/AGR-assets/maf`, каталог 931, манифесты, A101) → выбор (нет в каталоге — Артём называет объект, без
подмены, D164; новая модель — лего со врезками, D165) → габариты ≤ 10 см (D094) → рёбра и ID материалов v007 →
ВПМ с UDIM после Ground (D210) → расстановка с утоплением 10 см (D095, D096) → НПМ на атласе 512 (конвертация /
параллельно) → UCX: у МАФ нет → проверки на чтении экспорта → витрина для Артёма → пакет.

### Горячие точки

- `library-version` — `library/README.md` называет актуальной v005, а D240 записал v007.
- `npm-candidates` — каталог — технический аудит; у 695 из 931 МАФ нет кандидата НПМ.
- `npm-light-tool` — облегчённой НПМ-версии как инструмента нет (`maf_npm_light.py` не создан).
- `uv-remap` — перенос UV на атлас только внутри `maf_site_set_build.py`.
- `budget` — МАФ 60 000 из 180 000 (D097); Ватутино 59 148; делит Артём (D167).
- `placement-tool` — расстановка вызывается из скрипта job; на Ground v015 не перезапущена.
- `checks-coverage` — 14 из 24 строк МАФ без автопроверки; `maf_findings` — только НПМ GroundEl.

### Красные блоки: решение

| Блок | Статус | Причина |
|---|---|---|
| `library-version` | открыта | README библиотеки отстаёт от D240 (v007, ID 33 `wood_pine`); холодный агент прочтёт v005 |
| `npm-candidates` | открыта | идентификация библиотеки (T-MAF-1) не сделана; кандидат по габаритам — не совпадение |
| `npm-light-tool` | открыта | ветка «конвертация» без инструмента: D164 / D236 строят его только если набор не влезает |
| `uv-remap` | открыта | общий инструмент переноса UV на атлас (шаг 6 плана #425) не выделен |
| `budget` | открыта | правило D167 действует: агент приносит 2–3 варианта, режет Артём |
| `placement-tool` | открыта | нет общей команды расстановки; тот же вопрос, что доработка 3 карты Ground |
| `ucx-fences` | снята | решение Артёма [D298]: UCX ограждениям и навесам МАФ не строятся при любой толщине — практика проекта выше прочтения регламента p.36 §13.2 (≤ 5 см); стадия «UCX» ссылается на D298 |
| `checks-coverage` | открыта | L2-пробелы листа МАФ (14 строк `none`) |

## Пакет и сдача

11 стадий: экспорт FBX (триангуляция только на экспорте, рабочий FBX рядом; D152, D198, D212) → `export_meta`
у каждого FBX (неизвестное — `unknown`) → свежее чтение экспорта → GeoJSON ВПМ (D220, D223) → пакеты
`agr package-npm` / `agr package-vpm` (D015, D224, D235) → валидатор и xView → чекер СИНТЕЗ → отчёт сдачи →
приёмка Артёма в Max → загрузка в СИНТЕЗ (код и FNO выдаёт СИНТЕЗ) → пакет Артёму (архив или сцена 3ds Max с квадами),
приёмку и передачу заказчику делает Артём (D300; УКЭП — заказчика, D163).
Команда `dt derive npm` на стадии экспорта — выгрузка НПМ ОКС из ВПМ-мастера.
