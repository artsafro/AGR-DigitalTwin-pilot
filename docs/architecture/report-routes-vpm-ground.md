# Карты маршрутов ВПМ ОКС и Ground (#1383)

Тот же метод, что у карты НПМ / ОКС (#1359, PR #1368): событийный штурм из YAML, схемы генерирует
`tools/architecture/route_map.py`, подписи на русском. Источники правды и сгенерированные файлы:

| Маршрут | YAML (правится руками) | Схемы (только генератор) |
|---|---|---|
| ВПМ ОКС | `docs/architecture/vpm-oks-route.events.yaml` | `vpm-oks-route.excalidraw`, `vpm-oks-route.svg` |
| Ground | `docs/architecture/ground-route.events.yaml` | `ground-route.excalidraw`, `ground-route.svg` |

Проверка: `uv run python tools/architecture/route_map.py --check` — выход 0, когда схемы совпадают с генератором
и каждая команда `agr` / `dt`, строка D, путь и владелец контекста существуют. PNG для просмотра лежат на Drive
(`G:/Мой диск/AGR-evidence/1383-route-maps/` + `SHA256SUMS.txt`), в git их нет.

Всё взято из существующих файлов репозитория (jobs/, ретро, рецепты R5 / R6, строки D). Стадии без своего
владельца в карте контекстов (Ground, высоты, расстановка, UCX) описаны как `local_contexts` внутри YAML маршрута:
они видны только этому маршруту и не меняют `contexts.yaml`.

## ВПМ ОКС

14 стадий: исходники → PartsList → Gate 1 → корпус (сразу ВПМ или mid-poly мастер, по задаче) → проёмы и окна →
кровля / парапет (R6) → декор → UV / UDIM и текстуры → UCX → export_meta и пакет → свежее чтение экспорта →
проверки / xView → СИНТЕЗ → сдано. Корпус, проёмы, кровля, декор и UV идут в 3ds Max через AGR Tools (D250) —
это кнопки панели, а не команды `agr` / `dt`.

## Ground

12 стадий: DWG / ПЗУ → граница и ноль проекта → покрытия по штриховкам и ID → рельеф (TIN) → квады →
текстуры по ID и UV по UDIM → юбка ≥ 1 м → UCX (только ВПМ) → расстановка МАФ / Флоры → экспорт НПМ / ВПМ и
пакет → проверки → СИНТЕЗ. Основа — рецепт R5, маршрут Ground v015 Ватутино, исследование высот #1330 (с решением
по Силикатному #1315), заметки КПП1 и ТЭЦ26.

### Стадии без команды agr / dt

| Стадия | Статус | Чем делают сейчас |
|---|---|---|
| `zero` | нет команды | функции `src/dt_ai/core/heights.py` (#1341), ноль = `h_relief` (D279) |
| `surfaces` | нет команды | скрипты job (`ground_parts.py` Ватутино), цвет ID = фон штриховки (Силикатный) |
| `textures` | нет команды | привязка текстур в job (`ground-textures.md`), проекцию делает Артём (Касаткино) |
| `ucx` | нет команды | UCX собраны в DCC отдельно, `assemble_delivery.py` берёт их из C:/x |
| `placement` | нет команды | движок `dt_ai.placement` вызывается из `jobs/VATUTINO-SITE/place_site.py` |
| `sintez` | нет команды | тот же запуск чекера, что у ОКС |

`agr ground` / `dt ground v015` есть, но собирает только Ватутино v015 (данные из `--job-dir`): рельеф, квады и
юбка — это одна команда, привязанная к одному участку.

### Горячие точки

- `hatch-colours` — цвет ID берут из фона штриховки, не из цвета линий; разметка на каждом стыке.
- `project-zero` — ноль = `h_relief` (D279); система высот unknown для КПП1 / ТЭЦ26; у Силикатного ±0.000 из ПЗУ.
- `tool-bound-to-vatutino` — общей команды рельефа для нового участка нет (Силикатный #1315).
- `steep-step` — ступень 80° Ватутино: обрыв TIN у подпорной стены без геометрии; исключения D150 / D191.
- `pairing` — 90 000 квадов (D192) заменено D157: ≤ 35 % треугольников; маршрут A (D193).
- `projection` — проекцию делает Артём после приёмки плоской подложки (Касаткино).
- `skirt-gap` — 20 рёбер с опуском 0 лежат на крутой полосе 80°; ТЭЦ26 требует опуск ≥ 1 м.
- `ucx-ground` — `agr ucx` заглушка; UCX Ground берутся из путей C:/x внутри скрипта сборки.
- `urns-outside` — урны 15E288 / 15E289 вне поверхности v015, нужно новое слово Артёма.
- `budget` — НПМ 166 336 из 180 000 (GND-04), ВПМ Флора 443 788; делит Артём (D167).
- `kpp1-ground-missing` — у КПП1 Ground другого автора нет; пакет без него, без синтетики (D262, D285).
- `xview-parked` — xView v015 не чистый, #371 запаркован, участок #298 на v014.
