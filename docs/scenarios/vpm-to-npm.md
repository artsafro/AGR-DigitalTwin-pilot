# Сценарий `vpm-to-npm` — принятая ВПМ → НПМ по практике Артёма (#1737)

**Кратко.** ВПМ первична; НПМ выводится из принятой ВПМ отдельной ячейкой. Бадик не перестраивается и не
правится, ProOptimizer не используется (Артём 2026-11-21). Этапы и команды — `docs/agents/SKELETONS.md`,
раздел `vpm-to-npm`; одна конфигурация `jobs/<ID>/skeleton.json`.

## Порядок Артёма

1. Сначала посчитать треугольники ВПМ (`tris-count`).
2. Всегда удалить интерьеры: внутренние стенки капсул, интерьерные UDIM (`remove-interiors`; список задаётся явно в
   `config.interiors` и показывается на Gate 1 листом).
3. Атлас НПМ, вся геометрия на атлас: `agr vpm-to-npm` переупаковывает карты ВПМ (`npm_atlas.py --copied-udims
   --glass-white`) и переносит UV общим экспортёром (`export_npm.py`).
4. Стекло — одним объектом, его UV на чисто белых пикселях атласа (`glass-merge`); материал стекла без текстуры.
5. Только если всё ещё выше бюджета (`standards/NPM_STANDARD.yaml` `oks_triangles_per_fbx_max` = 150000), по порядку:
   меньше сегментов у цилиндров → ограждения и кондиционеры одной плоскостью с opacity → последним окна и витражи
   плоскостями с изображением окна на атласе (`budget-ladder`; отчёт ran / skipped / missing).
6. Далее `master-qa`, `readback`, `verifier`, `package-npm`, `validate`, `checker`, `review-scene`.

## Команда

```
uv run python tools/derive/vpm_to_npm.py --job jobs/<ID> --out C:/x/<topic>/run-vNNN
```

Exit 0 — в бюджете, 1 — выше бюджета (нужный шаг лестницы не подан), 2 — ошибка входа или этапа.
Входной VPM не меняется; выходная папка должна быть новой. `config.npm` задаёт `address`, `prefix`, `index`
явно; `config.atlas.opacity`, если задан, сопоставляет UDIM отдельной карте маски. Экспорт, метаданные и запись
деривации принадлежат общему `agr vpm-to-npm`. Отдельный ОКС без Ground можно упаковать через
`agr package-npm <run>/npm --allow-incomplete`: это диагностический пакет, выход 1, не готовая сдача.
