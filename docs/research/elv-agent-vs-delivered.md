### Геометрия и альбом

Blender 5.1.2, два отдельных импорта в метрах, без ICP/сдвига. Ближайшая точка на треугольной поверхности **того же экспортного компонента**; все вершины + детерминированная подвыборка центроидов. Это направленные выборочные расстояния, не точный непрерывный Hausdorff; для объединённого Main нельзя подтвердить авторское соответствие соседних деталей. UCX не сравнивается по расстоянию: аналога в рабочем FBX нет.

## Контракт GeoJSON

`SM_<Address>.geojson`, UTF-8, `FeatureCollection` с одним `ObjectFeature`, `geometry.type=Point`; `[X,Y]` **МСК‑77** в метрах (не longitude/latitude, не WGS84, до трёх знаков). Отдельного поля CRS в принятом файле нет. Горизонтальная привязка не задаёт систему высот. Для нового пакета использовать утверждённую точку установки по СПОЗУ/паспорту и проверить `export.pivot_place`; не восстанавливать MSK из локального `(0,0,0)`.

## Контракт Light FBX

`SM_<Address>[_Ground]_Light.fbx` — имя **файла**. В принятом бинарном FBX 7400 один `Null` `Elevatornaya_1_Root`, translation/rotation = `(0,0,0)`, scale = `(1,1,1)`; 29 непосредственных дочерних `Light` типа Spot с имёнами `Elevatornaya_1_Spot_001`…`029`; вложенной геометрии нет. Например, у Spot 001 локальные T ≈ `(−39.238, 22.286, 1.941)`, R ≈ `(90, −180, 0)` градусов, S `(1,1,1)`. Ненулевые T/R источников допустимы. Не переносить их координаты между разными моделями без сверки корневого pivot.

Этап `light-fbx` читает V012 из `agr validate ZIP --profile vpm` и проверяет наличие строки Light, когда файл света запланирован: один reset Null, типы Spot/Omni, прямое родительство, уникальные имена с Address, конечные XYZ. Однородные имена с `SM_` сохранены для ранее экспортировавшего их AGR Tools; смесь форм отвергается. Действующая проверка номера 001–050 оставлена без расширения по единственной выборке 001–029; общий лимит 250 не изменён. Совпадение pivot с моделью, дистанции источников и световой дизайн не подтверждаются этим бинарным чекером.
