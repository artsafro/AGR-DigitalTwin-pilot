# AGR Tools: модуль `assets` — браузер и импорт ассетов (Flora, МАФ)

Часть #1024 (конвейер AGR Tools 1.0), отдельная задача. Ветка `improve/issue-1024-assets-flora`.
Статус: Flora и МАФ — индекс, окно и импорт работают, проверено в Max 2024. МАФ импортируется из архивов A101, как
у плагина AlexYo. Общая библиотека для агентов — `library/assets/` (A101 — истина, плюс прежние библиотеки
пилота). Сверка с хелперами («Сопоставить») реализована в ядре, кнопки в Max пока нет. Расстановка — только
интерфейс к `place.schedule`.

**Решения Артёма 06.11.2026:**
- пивот и посадка растений A101 — стандарт, остаются;
- роль `agr_role` импортированным растениям и МАФ не нужна;
- Ctrl+Z после импорта не важен, откат — кнопкой «Убрать импортированное»;
- недостающие превью можно сделать самим, «по тому же типу», что снимки вьюпорта A101;
- A101 — истина по названиям и артикулам; прежние библиотеки и растения агентов, которые выглядят нормально,
  добавляются в общую библиотеку.

## Источник идей
Плагин коллеги AlexYo Asset Importer 1.0.2 (`AlexYo_AssetImporter_v1.0.2.mzp`, SHA256
`4c910813510698f417a43bb9617630e2134fe7541f4c0a84a44b2e481db28a9d`). Исходник и разбор логики лежат в
GeoAGR-private: `sources/team-scripts/alexyo/`, `work/team-scripts-audit/alexyo-asset-importer.md`,
ветка `assets/alexyo-source`. По правилу #853 код в пилот не копируется. Взяты только идеи:
- индекс по оглавлению zip без распаковки и кеш превью;
- карточка с бейджем High/Low, список выбранного;
- настройки сохраняются между сессиями;
- merge выбранных имён с политикой материалов, перепривязка текстур по basename;
- раскладка от начала координат, изоляция сбоя одного ассета.

Чем пилот отличается от плагина:

| | AlexYo 1.0.2 | `assets` |
|---|---|---|
| Источник | zip в корне библиотеки | Flora (один .max + превью) и МАФ (zip, рекурсивно, с подпапками) |
| Целостность | mtime+size | + SHA256 источника в индексе и в user props каждого объекта |
| Поиск | одна подстрока | токены по имени, производителю, названию, артикулу, виду, t/h; ё = е |
| Метаданные | — | sidecar `<имя>.json` (schema 3) из архивов МАФ A101 |
| Повторный импорт | создаёт дубли `_high001` | пропускает то, что уже в сцене (`already_in_scene`) |
| Merge | из распакованного .max | из проверенной копии `.max` в кеше; оригинал на Диске только читается |
| Журнал | — | строка журнала К1 и запись в паспорт |
| Единицы | `decodeValue "1.0m"` | `units.SystemScale` |

ствола (дерево) или в центре bbox (куст), посадка 5–10 см». D100 относится к библиотеке v003.
`place.schedule` ставит пивот в точку, поэтому дополнительно опускать растения A101 не нужно.

### Черновик контракта «библиотечное растение» (для агентов и проверки новых ассетов)
1. **Имя:** `<вид>_t<тип>_h<см>`, версии `_high` (ВПМ) и `_low` (НПМ). Обе версии обязательны.
2. **Пивот:**
   - дерево — у основания ствола (|центр низа − пивот| ≤ 0,1 м);
   - куст — центр bbox XY;
   - пивот на 0,05–0,10 м выше нижней вершины, одинаковый у ВПМ и НПМ.
3. **Трансформ:** scale 1, без поворота и сдвига.
4. **Геометрия:**
   - ВПМ — 3D-крона и ствол;
   - НПМ куста — крест 2 квада (4 треугольника);
   - НПМ дерева — упрощённая 3D-модель.
   Треугольники в образцах: ВПМ 164–2176, НПМ 4–866. Бюджет — по аудиту #189, не здесь.
5. **Материал:** один Standardmaterial с именем объекта; diffuse + opacity из одного RGBA PNG; twoSided off.
6. **Текстуры:**
   - `<base>_high.png` 2048² или 4096², `<base>_low.png` 2048²;
   - тексель ВПМ ≈ 900–1400 px/м, НПМ дерева ≈ 450–510 px/м;
   - путь — по basename в `TextureFlora`.
7. **Превью:** `PreviewFlora/<base>_PREVIEW.png`, имя точно совпадает с base.

Проверка нового ассета по этим пунктам — следующий шаг (`assets.check_plant`). Метрики выше получены на 6 образцах,
это не норматив.

- Прочитаны все 70, битых нет.
- 62 архива с sidecar JSON, 8 без него — все из `3.1_ЮС`.

Состав архива `Производитель_Объект_Артикул.zip` (Q28; в артикуле бывают `-`, `.`, буквы):
```
<имя>.max  <имя>.png (превью)  <имя>_high.fbx  <имя>_low.fbx  [<имя>.json]
T_<имя>_high_Diffuse|ERM|Normal.png (4096²)   T_<имя>_low_d.png (512²)        — 2026-08 экспорт
<имя>_high_Diffuse|ERM|Normal.png   <имя>_low_d|m|n|o|r.png                   — архивы 3.1_ЮС
```

Sidecar (schema 3) содержит:
- identity: manufacturer / object_name / article;
- `units: mm`, `up_axis: Z`;
- versions, polycount, `geometry.<ver>.object_names`, bbox, пивот (`above_bbox_base_mm`), трансформ;
- materials, textures со слотами и разрешением;
- `fbx_export` (m, Y-up, FBX201400);
- `geometry_hash`.

Адаптер берёт из sidecar имена объектов версий и метаданные. Если identity расходится с именем файла, это попадает
в предупреждения.

**Индекс** (`<кеш>/<lib>_assets_index.json`, атомарная запись). Для каждого ассета:
- `id` = `<lib>:<имя>`; kind; имя; производитель, название, артикул (МАФ);
- вид, тип, высота (Flora);
- `versions.{high,low}.objects`; превью и способ совпадения (exact / fuzzy / none);
- `source` {path, sha256}; meta (sidecar); warnings.

`sources` хранит size, mtime, sha256 и (для Flora) список имён объектов. Повторный скан неизменённой библиотеки
не открывает .max и не перечитывает zip. SHA: у Flora считается при скане (25 МБ), у МАФ — при импорте (на
стримящемся Диске гигабайты).

**Импорт** (Flora, MAX):
1. План: что брать, что уже в сцене, каких версий нет.
2. Проверенная копия `.max` в `<кеш>/sources/<sha12>_<имя>`.
3. `mergeMAXFile` выбранных имён с флагами `#autoRenameDups`, `#useSceneMtlDups` («из сцены») или `#renameMtlDups`
   («копия»: Max называет такой материал `Material #N`, мы переименовываем в `<объект>_copy`), `#neverReparent`.
4. Слой `ASSET_<lib>_<high|low>`; user props `agr_asset_id`, `agr_asset_version`, `agr_asset_lib`,
   `agr_asset_sha256`.
5. Текстуры по basename: копия в `<проект>/assets/<lib>/textures/` или ссылка на `TextureFlora`.
6. Раскладка от начала координат: колонка на ассет — High впереди, Low за ним по +Y; колонки по +X, перенос строки
   по `row_limit_m`; пивот на z = 0.
7. Одна запись Undo, строка журнала К1, запись в паспорт, если он передан.

**Расстановка и сверка (интерфейс, по дополнению оркестратора 06.11).**
- `match_names(helpers, [индексы], aliases)` — кнопка «Сопоставить». Имена хелперов или блоков DWG сопоставляются
  с индексами Flora и МАФ (точно → алиас → префикс `lipa` → `lipa_t1_h550`). На выходе по каждому имени:
  количество и статус `matched` / `ambiguous` / `missing`, плюс итог `green`. Хвост `001` снимается, только если
  полного имени в библиотеке нет: артикулы МАФ сами кончаются цифрами.
- `reconcile_spec(spec, match, индексы)` — сверка со спецификацией альбома: `ok` / `short` / `excess` /
  `not_in_library` / `no_helpers`. Чего нет в библиотеке, превращается в задачи `add_to_library` для агента или
  человека. Сверка зелёная, только когда всё `ok`.
- `placement_rows(helpers, match, kind, seed)` готовит строки в формате `place_core.schedule_plan`:
  - МАФ — позиция и поворот хелпера;
  - Flora — позиция, поворот 0 или случайный вокруг Z по seed.
  Сама расстановка — существующим `place.schedule` (посадка на Ground) или агентом через мост U (К4).
  Здесь она не реализована.
- Скрипт экспорта DWG от Андрея в GeoAGR-private `sources/team-scripts/` не найден. Ближайшее — `EXPORTCIRCLESCSV.lsp`
  (центры окружностей → CSV X;Y;Z, SHA256 `0b285d1e…`) и `rename_maf_and_split_plants.py` Артёма (`35bacdf0…`).
