**Гипотеза 256 px — подтверждена (изм.):** вход каждой команды `prepareTile` — 256×256 (`GeoAGR.ms:27440`, `:27298-27324`).
При текселе 358 px/м для панелей это апскейл; при правильной цели 39 px/м и периоде 1 м 256 px хватило бы, но Priority цель
не держит: TD считается по корню площади всей группы (`:27531-27536`), а у уложенных стопкой кусков (К6) реальная плотность

## Дефекты GeoAGR (изм., кроме помеченных)
1. Тайлы Priority из рендера 256 px (`:27440`).
2. Тексель не по цели, разный между ID (×10); в сантиметрах ограничение TD не работает (`:27531-27536`).
3. Остров больше 1 UV: Priority — пустота (`prepareTile`, комментарий автора `:27096`), классика — растянутые края
   (`fit_map_new` `:1152`).
4. `copyFile` не перезаписывает: устаревший `Tile_*` из `%TEMP%` попадает в атлас (`:27588`).
5. Перезапись атласов без вопроса; attach выбранных объектов без копии (`:26817-26828`).
6. Стекло — ячейка цвета диффуза, прозрачность теряется; roughness и metal в слотах reflection/glossiness перепутаны (`:27665`).
7. Цвета меняются при рендере Priority в Max 2026 (гип.: настройки цвета Max 2026; 2024 не мерилось).
8. Путь проверки заглушек `Tile_C:\…` (`:27638`) — команды падают.
9. Коды выхода EXE не проверяются: когда EXE не найден, классика молча собирает чёрный атлас 128×128 (изм. в окружении
   агента с `NoDefaultCurrentDirectoryInExePath=1`, джобы `20261106-003405-prio_m`, `20261106-003936-classic_m`).

## Вердикт лаборатории: `new`
- **Брать (идею):** жёсткий перенос группы ID с прокруткой — один равномерный масштаб и один сдвиг на группу, дробное
  начало группы сохраняется. Измерено: шов К6 остаётся 0.
- **Не брать:** рендер 256 px и `renderMap`, TD по площади группы, растягивание краёв `fit_map_new`, attach без копии,
  фиксированные имена в `%TEMP%`, Shell-материал и раскладку слотов, сборку без проверки кодов выхода.
- **Как в прототипе AGR (изм.):** масштаб ID = цель / тексель ВПМ; ячейка — исходная карта, повторённая по реальному
  охвату UV группы (viewport в бесконечно замощённую карту, один ресайз); поле = продолжение той же текстуры; полка;
  стекло белое; заглушки — цвет; таблица соответствия пишется рядом с атласом.

## Минимальная приёмка
Синтетика лота (`L11_buildVPM`, карты с закодированной координатой) и KPP1 ВПМ, Max 2024 и 2026, метры и сантиметры:
1. **Тексель.** Все текстурные ID в атласе = цель ± 1 % (на синтетике 39,0 px/м); одинаково в м и см.
2. **Шов К6.** Метрика шва внутри каждой группы ID = 0 текселей (≤ 0,01 при 1024 px/м).
3. **Текстура и UV.** Скачки закодированной карты в атласе — в пределах 0,25 px от положения по UV; 0 пустых и 0
   растянутых точек у острова 3 × 2,5 UV.
4. **Источник.** Ячейки строятся из карт полного разрешения (в журнале — размер входа = размер исходной карты).
5. **Цвета.** Заглушки и пиксели текстур в атласе = исходным (разность ≤ 1 уровня); стекло — белая ячейка, грани стекла в
   объекте НПМ.
6. **Исходники.** Хэши ВПМ-объектов и карт до и после равны; ни один узел не удалён.
7. **Файлы.** Существующий атлас не перезаписывается (новое имя или отказ); старые файлы во временной папке не влияют
   на результат.
8. **Таблица.** Для каждого ID: исходный UDIM по паспорту, материал библиотеки, карта, масштаб, сдвиг, ячейка;
   `npm.to_vpm` по ней возвращает UV ВПМ (см. `npm.to_vpm.md`).
9. **Ошибки.** Недоступная внешняя программа или пустой результат → отказ с сообщением, атлас не пишется.
