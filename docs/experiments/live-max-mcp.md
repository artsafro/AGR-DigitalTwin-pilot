# L12 — живой 3ds Max через MCP для UI-тестов (#1024)

Лаборатория AGR Tools 1.0, лот L12, ПК No_Defender, 3ds Max 2026. Доказательства — GeoAGR-private, ветка
`lab-exp/10-L12`, `work/lab-experiments/live-max-mcp/`. Метки: **изм.** (с job id), **стат.**, **гип.**

**Статус: частично. L12 ждёт PR пина agr_mcp** (`improve/issue-1024-mcp-runtime-pin`, ветка 0). По решению Артёма
(06.11) UI-тесты идут через `src/agr_mcp`, а не напрямую через 3dsmax-mcp; поэтому нажатие кнопок, Undo, выделение,
снимок панели и проба дока ещё не выполнялись. Измерена изоляция экземпляра.

## Что измерено
- **изм.** `20261106-011955-live1`: отдельный GUI Max 2026 в изолированном слоте (`max2026-1`, собственные `3dsMax.ini`
  и `Plugin.UserSettings.ini`, тот же лок, mutex и guard профиля, что у batch-раннера) запущен и закрыт;
  защищённые файлы профиля Артёма (`ENU\en-US\UI`, `ENU\Network`, 58 файлов) после закрытия совпали по хешу.
- **изм.** там же: регистрация макросов при старте (бандл AGR Tools из профиля, 3dsmax-mcp) уходит в папки слота;
  в папки Артёма ничего не пишется, его стартовые скрипты в слоте не исполняются.

## Что известно статически
- **стат.** MCP-мост 3dsmax-mcp установлен на всю машину и грузится в любой Max, в том числе в GUI Артёма. У каждого
  окна свой канал; клиент обязан указывать PID экземпляра. `agr_mcp` уже отказывает без `AGR_MCP_MAX_PID` — так и
  должно остаться.
- **стат.** В профиле Артёма стоит пакет AGR Tools 0.7.0, он загрузится и в изолированный экземпляр. Тестируемая
  версия подгружается из копии пакета внутри экземпляра; профиль Артёма не меняется.
- **стат.** Найден сторонний запуск `3dsmax.exe -batch` мимо общего раннера (другая сессия, без слота и guard) —
  риск для UI Артёма; сообщено оркестратору.

## Claude-док внутри Max (дополнение ветки U) — подготовлено, не запускалось
Проба проверит: `QDockWidget` (PySide6 6.5.3 есть в Max 2026, стат.) стыкуется рядом с панелью AGR Tools; локальный
`claude` (CLI на ПК установлен) запускается через `QProcess` в режиме stream-json без блокировки UI (таймер-пульс),
поток читается построчно; при недоступности CLI — фиктивный процесс с тем же форматом; вызов операции сцены из
фонового потока выполняется на главном потоке Max через очередь и даёт одну запись Undo.

## Вердикт
`take` для схемы «изолированный слот + guard + PID-пин»: изоляция подтверждена (изм.). Осуществимость UI-тестов
(Undo, выделение, вид панели, док) — **гип.**, проверка после слияния пина agr_mcp.

## Минимальная приёмка
1. Запуск изолированного Max и закрытие: защищённые файлы профиля Артёма совпадают по хешу (58/58), в его папках
   макросов и скриптов нет новых файлов. *(выполнено, `20261106-011955-live1`)*
2. Лаунчер отказывается стартовать, если открыт GUI Max той же версии.
3. Через agr_mcp с `AGR_MCP_MAX_PID`: синтетическая сцена, `place.drop_to_ground` и `place.replace` preview → apply;
   ровно одна запись Undo на apply (один Undo возвращает сцену по хешам трансформов); выделение после кнопки равно
   выделению до неё.
4. Снимок панели AGR Tools в Dark и Light, PNG в доказательствах.
5. Док: виден и пристыкован; фиктивный stream-json — все строки получены по одной, пульс UI не прерывался;
   `claude -p` — строка `result` получена (или зафиксировано «CLI не авторизован»); операция из фонового потока —
   одна запись Undo.
6. `agent.accept`: операция в слое `AGENT_*`, нарушение инварианта → откат, исходные хеши вне слоя.
7. Время сценария записано; после `quitMax` guard снова «verified identical».
