## Этап 2 (L12b): agr_mcp против изолированного Max — измерено
Пилот main `c6921137` (пин agr_mcp #1052, MCP v2 #1058). Изолированный экземпляр — job `20261106-023128-live2`;
измерения — job `20261106-023254-agrmcp`: клиент MCP SDK → сервер agr_mcp (`AGR_MCP_MAX_PID` = PID экземпляра) →
канал 3dsmax-mcp → мост → AGR Tools 0.9.0, установленный в папку прогона. Инструменты 3dsmax-mcp напрямую не
вызывались.
- **изм. Латентность** (хост → Max → хост, мс): пустой вызов канала — медиана 286; `agr_check_run` — медиана 414
  (303–681, n = 10); `agr_op_preview` — 375; `agr_op_apply` — 341; нажатие кнопки панели — preview 340, apply 429.
  Экземпляр готов к вызовам через 21 с после старта; весь сценарий от старта до выхода — 172 с.
- **изм. Одна запись Undo на apply:** `ucx.rename` через MCP (preview → `preview_id` → apply) — один Undo
  возвращает оба имени, второй Undo имён не трогает; `place.drop_to_ground` кнопкой панели (preview не двигает,
  apply опускает на Ground) — один Undo возвращает оба объекта.
- **изм. Выделение** восстановлено после каждого вызова: `agr_check_run` 10/10, preview и apply, оба нажатия кнопки.
- **изм. Шлюз apply:** apply строки 0.9 через MCP отклонён `needs_human`, сцена не меняется; preview через MCP
  разрешён и ничего не двигает.
- **изм. Журнал:** по строке на вызов; `actor` различает `mcp` и `panel`.
- **изм. Изоляция:** профиль Артёма после выхода совпал по хешу (58/58). Штатный выход GUI переписывает его
  usersave-раскладку — guard её откатывает, поэтому живой экземпляр запускается только лаунчером со слотом и guard.
- **изм. Найден дефект `ucx.rename` (0.8):** адрес берётся из имени куска без приведения регистра к модели:
  при модели `SM_Lab_12_Main` куски дают `UCX_SM_lab_12_Main_001` и `UCX_SM_Lab_12_Main_001` — имена различаются

- **изм.** `quitMax` через канал отвечает ошибкой «interrupted», хотя Max завершается с кодом 0 — клиенту ждать
  выхода процесса, а не ответа.

**Рецепт ночного прогона:** лаунчер слота → ждать готовности канала → `AGR_MCP_MAX_PID=<pid>` → сценарий клиента
MCP SDK → `quitMax` → guard «verified identical».

## Claude-док внутри Max (дополнение ветки U) — подготовлено, не запускалось
Проба проверит: `QDockWidget` (PySide6 6.5.3 есть в Max 2026, стат.) стыкуется рядом с панелью AGR Tools; локальный
`claude` (CLI на ПК установлен) запускается через `QProcess` в режиме stream-json без блокировки UI (таймер-пульс),
поток читается построчно; при недоступности CLI — фиктивный процесс с тем же форматом; вызов операции сцены из
фонового потока выполняется на главном потоке Max через очередь и даёт одну запись Undo.

## Вердикт
`take` для схемы «изолированный слот + guard + PID-пин + agr_mcp»: изоляция, латентность, одна запись Undo,
восстановление выделения и шлюз `needs_human` измерены (этап 2). Вид панели и док — ещё **гип.**

## Минимальная приёмка
1. Запуск изолированного Max и закрытие: защищённые файлы профиля Артёма совпадают по хешу (58/58), в его папках
   макросов и скриптов нет новых файлов. *(выполнено, `20261106-011955-live1`)*
2. Лаунчер отказывается стартовать, если открыт GUI Max той же версии.
3. Через agr_mcp с `AGR_MCP_MAX_PID`: preview → apply строки 0.8 (`ucx.rename`) и кнопка панели для строки 0.9
   (`place.drop_to_ground`); ровно одна запись Undo на apply; выделение после вызова равно выделению до него;
   apply строки 0.9 через MCP → `needs_human`. *(выполнено, `20261106-023254-agrmcp`)*
3a. Латентность `agr_check_run` ≤ 1 с медианой на синтетике из 6 объектов (измерено 414 мс).
3b. `ucx.rename`: куски модели `SM_Lab_12_Main` с именами в разном регистре дают один набор
   `UCX_SM_Lab_12_Main_NNN` (сейчас RED).
4. Снимок панели AGR Tools в Dark и Light, PNG в доказательствах.
5. Док: виден и пристыкован; фиктивный stream-json — все строки получены по одной, пульс UI не прерывался;
   `claude -p` — строка `result` получена (или зафиксировано «CLI не авторизован»); операция из фонового потока —
   одна запись Undo.
6. `agent.accept`: операция в слое `AGENT_*`, нарушение инварианта → откат, исходные хеши вне слоя.
7. Время сценария записано; после `quitMax` guard снова «verified identical».
