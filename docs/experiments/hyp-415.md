# Hypothesis #415 — per-file PNG decode isolation

**Verdict: CONFIRMED.** Every rejection threshold passed on the candidate (arm B). The
candidate catches only the expected Pillow decode `OSError` (12 plain `OSError` +
6 `UnidentifiedImageError` across 18 corrupt decode inputs), emits one filename-specific
`fail / PNG readable` per broken member, excludes that member from the returned VPM map
sets, and continues the other members. The three unchanged focused test files run
identically under baseline and candidate (**326 passed**, identical node ids and outcomes),
all six successful-return/header-only parity controls are byte-identical, both mixed-package
slots continue with their unaffected findings, and all four outer `validate()` reports are
returned with `passed=False` and strict-JSON serialization. `MemoryError` / `RuntimeError` /
`TypeError` injected at the `pixels()` boundary propagate (12/12), never become input
findings. `delivery_passed=false`; every PNG/ZIP is synthetic, not data of a real object.

## Claim (issue #415)

Localizing expected Pillow identification/decode `OSError` failures at the existing
per-file pixel-read boundaries in `twinqa.png` makes mixed-input NPM/VPM validation
continue, without changing any existing successful-return texture verdict, heuristic, or
header-only acceptance behaviour. Compatibility / no-regression hypothesis; the corrupt-PNG
witnesses are regression controls only.

  `tests/qa/test_validator.py`, `tests/qa/test_png_fixed_field_errors.py`,

native exports.
