## Что из Blender-пути не переносится в Max
1. DCC-адаптер. Импорт библиотек с запеканием поворота и масштаба, факты, инстансы, удаление дна, readback — для Max не
   написаны. Стенд лаборатории показал, что их можно повторить 1:1 (0 расхождений).
2. numpy и shapely. В Python Max их, по обходу AGR Tools «when Max lacks numpy» (`adapters/max/agr_tools/runtime.py:1844`),
   нет; в джобе не проверялось (гип.). Движок — вне процесса Max.
3. Хранение запуска и повтор. Blender пишет новый `.blend` и run record. В Max нужны свойства файла (seed —
   работает) и защита от повторного прогона по handle (без неё — дубли, изм.).
4. Матрица. У движка row-major 4×4 для столбцов, у Max в `matrix3` строки = оси. Перевод проверен (изм.).

## Вердикт лаборатории: `new` (без изменений)
- Порт report-first.
- Движок — вне процесса.
- Max-адаптер — как стенд лаборатории.
- Каждая позиция получает строку отчёта: поставлено / нет эталона / вне Ground / пересекает здание. Полная остановка
  остаётся опцией.
- Повтор идемпотентен по handle.
