# Master -> NPM/VPM derivation — L1 requirement sheet

Area: what the one mid-poly master per OKS FBX contains and what each delivery profile removes or adds when NPM and VPM are derived from it (roadmap §7.7 T-DER-1). See [roadmap §7.7](../../research/capability-roadmap.md#77-master--npmvpm-derivation--l1-partial-new-node).

Out of scope: BODY/window/decor construction, UV/atlas production, UCX construction, Ground, the package sheet (T-PKG-1: ZIP size/composition limits); they appear only as derivation interfaces.

Readiness: roadmap records derivation as **L1-partial**; logic lives in job scripts `jobs/KPP1/scripts/` and `jobs/PSU275/scripts/` (`export_npm`, `make_npm_atlas`, `package_vpm`, `qa_master`, `run_all`), duplicated per job; T-DER-2 (shared `dt derive`) and T-DER-3 are not done. No model is built or certified here. Engine profiles `npm_min` / `mid` are not delivery certificates.

This is an index, not a replacement rulebook. Sources: `reg p.N` = one-based physical page of [the regulation](../../../standards/source/Rasporyajenies19012026trebovaniya(2).pdf); `§A.B.C` = row A of the page's requirement table, item B.C (e.g. reg p.33 §10.4.1 = row 10, item 4.1); `§4` on p.4/p.24 = section 4 "Порядок подготовки". Decisions: [decision log](../../decisions.md). `L2 coverage` names implemented checks only; `none` = no automatic check today. Conflicts are only pointed to [conflicts](../conflicts.md), never decided.
